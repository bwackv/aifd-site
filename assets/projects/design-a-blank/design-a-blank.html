Design a ____

interpret an intentionally vague prompt and use a.i. to make it into something

01The Brief

Read this first.

Pick one of the three prompts below. Your job is not to write code — it's to direct the A.I. to build a website in HTML, CSS & JavaScript that reflects your interpretation. 

The prompt is intentionally vague. Feel free to take creative license.

02Your Prompt

Pick one. The blank is yours to fill. Have a better idea than these three? Go with it (just run it by me first).

Clock

“Make a clock.”

A sundial? A Dalí clock? A clock made of words? A countdown to something? You decide.

Vending machine

“Build a vending machine.”

What does it sell? What does it look like? Is it from the future, the past, or another planet?

Shrine

“Build a shrine.”

To what? To whom? A memorial, a fan altar, a glowing neon temple, a single candle in a dark room?

03The Rules

How it works.

  • You have the rest of the class time to start on this. We will continue it in class on Wednesday.
  • Use Copilot. If Copilot will not do something, try another A.I. — ChatGPT, Gemini, Claude.
  • Decide which of the three prompts to pursue, then start by asking the A.I. to brainstorm with you.
  • Ask for it as a single downloadable HTML file — all the HTML, CSS and JavaScript in one file. Not code on the screen for you to copy.
  • You don't write the code — the A.I. does. You direct.
  • Iterate. Don't accept the first thing it gives you. Push it further.

04Hand-In

When time's up.

  • Bring your HTML file to class on Wednesday.
  • You will learn how to post it once you have made your course website.
  • We'll look at a few together as a class.

05Worked Example

How I built “ART-O-MAT” with A.I.

I built a vending-machine site with Claude. Here's what the process actually looked like — including the parts where the first version wasn't good enough and I had to push the A.I. harder. Be sure to push your project as far as you can! 

1  The first prompt

  • I told Claude: “Build a vending-machine website. I want it to vend unknown artworks by masters — Degas, Picasso, Jenny Saville, Yayoi Kusama. It should have a pop-art halftone feel.”
  • What came back: a working machine with a coin slot, a crank handle, halftone dots, comic-style type, and a collection tray. The structure and interaction were solid but...

2  What was wrong

  • The “paintings” were just emojis — a ballet slipper standing in for a Degas, a guitar for Picasso's Old Guitarist. A placeholder, not a design.
  • The machine itself looked good — the pop-art style, the halftone, the interaction — but the art it was vending felt lazy.
  • See the first version

3  Going back in — defining the artists

  • I told Claude: “The paintings are crappy. Define each artist's visual style, then build CSS paintings that actually feel like their work.”
  • We broke it down artist by artist:
  • Degas — soft pastels, warm ochres, blurred motion, diagonal compositions, dancers mid-gesture.
  • Picasso — bold black outlines, fragmented geometry, flat colour planes, several viewpoints at once.
  • Jenny Saville — flesh tones, thick impasto, layered transparency, warm pinks and reds bleeding together.
  • Kusama — polka dots, infinite repetition, vivid colour fields, hot pink and yellow, layered dot grids.
  • Then I asked for three CSS paintings per artist — twelve in all — built from gradients, shapes, patterns, and layering. No images. Just code.
  • See the CSS paintings gallery

4  Putting it together

  • Once the paintings existed, I had Claude swap the emoji for the real CSS paintings inside the machine.
  • I pushed on layout too: “Make it fill most of the screen. The body text is hard to read on the halftone — add a semi-transparent red behind it.”
  • Small tweaks, but they make a difference. 
  • See the final version

5  What else could be done (you should keep going, my demo is limited)

Beyond my own ideas of further changes such as making it dynamic with an evolving roster of artists, I asked Claude what to add next. It came back with:

  • A “mystery” button — generates a brand-new painting on the fly in one artist's style, so you get something never seen before.
  • Ornate gold frames — CSS-rendered around each painting, to sell the gallery feel.
  • Sound effects — a coin clink, a crank grind, a soft thud on drop, synthesised with the Web Audio API, no files needed.
  • A “sold out” mechanic — once all twelve are vended, the machine flashes, shakes, and resets.
  • An animated reveal — the painting drops wrapped in paper that peels away, building anticipation.
  • The point: you can always keep going. The A.I. doesn't run out of ideas — you just have to keep asking. It may run out of good ideas, though. 

6  Takeaway

  • The first version took one prompt. The good version took a conversation.
  • The A.I. doesn't know what “good” looks like for your project — you do. Look at what it gives you, find what isn't working, and tell it specifically what to fix.
  • The more specific the feedback, the better the result. “The paintings are crappy” is a start; “define each artist's style and build CSS paintings that match” is better.

This is experimental. There's no wrong answer. The goal is to get your hands on these tools, see what they can do, and start forming your own sense of how to direct them. Go weird.
