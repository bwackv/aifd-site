Session 3: Human-in-the-Loop Evaluation & Debugging

Goal: Test the AI’s output, identify failure points, and refine the orchestration files.

01Overview

6.1 · Mon Oct 5 · online

  • Stress Testing: Run the generated web app. Attempt to recreate a Müller-Brockmann Tonhalle concert poster layout.
  • Visual Debugging & Hierarchy Check:
    1. Take screenshots of layout failures.
    2. Analyze where the AI failed to respect the typographic hierarchy—is the contrast between the display type and text sizes muddled? Did the AI override the carefully sourced Google Fonts with defaults?
  • AI Self-Correction:
    1. Feed the failure screenshots back to a separate AI chat.
    2. Ask it to analyze the problem areas and rewrite the prompt and skills.md to fix structural math and enforce the typographic scale.
  • Task:
    1. Implement fixes.
    2. Export a test SVG/PDF.
    3. Open it in Adobe Illustrator to verify vector path integrity.
    4. Evaluate if the output moves closer to the historical reference material.

02In class

100 minutes

small group visual debugging session. Have students collaboratively critique one another’s approaches to the project.

  • 40 min: Group visual debugging session. Sharing failed outputs and identifying the math/logic errors in the AI’s CSS or SVG generation, specifically focusing on broken typographic hierarchies.
  • 60 min: Practicing “AI Self-Correction”—feeding screenshots back to the LLM to rewrite the broken logic and enforce rigid font sizing and cadencing.

03Homework

4–5 hours

  • 3 hours: Deep iteration. The application must move from “barely working” to “stylistically accurate.” You will likely need to reset the AI context window using your updated handoff.md at least twice.
  • 1–2 hours: Generating the final series of test posters using the refined tool. Tuning typographic hierarchies, testing SVG/PDF exports in Adobe software, and validating spatial rhythms.
