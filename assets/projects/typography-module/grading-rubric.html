AI-Aided Generative Typography: Visual & Systemic Grading Rubric

Evaluation Focus: This rubric assesses the final GitHub repository and the generative output of the web application. While the code must function, the primary grading emphasis is placed on visual rigor: the fidelity to historical Swiss typographic principles and the generative inventiveness of the resulting system.

01Typographic Analysis

10 points

Core Question: Does the student’s written deconstruction of the archival reference demonstrate genuine visual observation? This is the raw analysis document produced in Session 1 and the skills.md rules derived from it.

  • Exceptional (9–10 points): The analysis names specific, measurable characteristics — scale ratios, weight relationships, the unit the spacing is built on, where the grid is broken and why. Observations are particular to the chosen poster and could not describe any other. The rules in skills.md map directly onto what was observed.
  • Proficient (7–8 points): The analysis identifies the major structural decisions correctly but stays general in places. Hierarchy and grid are described; finer relationships (x-height, stroke contrast, spatial rhythm) are noted loosely or missed. Most observations survive into usable rules.
  • Developing (5–6 points): The analysis relies on impression rather than observation (“clean,” “modern,” “balanced”) without identifying the decisions that produce the effect. Little of it converts into constraints the tool can enforce.
  • Insufficient (0–4 points): Missing, or describes the poster’s subject rather than its design.

02Archival Aesthetic Fidelity

30 points

Core Question: How closely and accurately did the student’s tool capture the foundational aesthetic decisions, grid logic, and typographic hierarchy of the original archival references (e.g., Müller-Brockmann, Weingart, Kunz)?

  • Exceptional (27–30 points): Masterful translation of the International Typographic Style. The output demonstrates a rigorous understanding of asymmetric grid math. Typographic hierarchy (scale, weight, contrast) perfectly mirrors the historical DNA. Unitized cadencing, spatial rhythms, and x-height relationships are historically accurate based on the AI-assisted font sourcing.
  • Proficient (22–26 points): Strong visual alignment with the archival references. The grid is present and mostly respected. Typographic hierarchy is clear, though minor spacing or scale inconsistencies may occur when the system is pushed. The selected Google Fonts adequately represent the neo-grotesque structural requirements.
  • Developing (15–21 points): The output resembles generic AI-generated design rather than strict Swiss Typography. Centered layouts, muddled type scales, or inappropriate font substitutions override the historical constraints. The tool fails to consistently enforce the archival aesthetic rules.
  • Insufficient (0–14 points): No clear relationship to the sourced visual history. Complete breakdown of grid logic and typographic proportion.

03Generative Inventiveness

30 points

Core Question: How inventively did the student stretch the rules? Did they build a tool that just clones one specific poster, or did they design a dynamic system capable of producing unexpected, creative variations that still feel authentic to the movement?

  • Exceptional (27–30 points): The application acts as a true design engine. It generates surprising, dynamic visual compositions that push the boundaries of the original archival constraints without breaking the underlying logic. The user inputs yield highly inventive, parametric variations (e.g., brilliant handling of image-to-color-palette extraction or novel typographic disruption inspired by Weingart).
  • Proficient (22–26 points): The tool produces good variations, but they may feel somewhat repetitive or safe. The system handles standard inputs well but lacks the parametric flexibility to truly surprise the user with inventive layout combinations.
  • Developing (15–21 points): The tool is essentially a static template. Inputs change the text or an image, but the structural layout remains rigidly identical every time. It lacks systemic flexibility and generative design thinking.
  • Insufficient (0–14 points): The tool does not generate variable outcomes or breaks entirely when novel inputs are introduced.

04Vector Architecture & Export Cleanliness

10 points

Core Question: Is the human-testable output (SVG/PDF) materially sound? Can it be utilized in a professional post-production workflow?

  • Exceptional (9–10 points): The exported SVG/PDF is flawless pure-vector math. When opened in Adobe Illustrator, the file features logical grouping, intact paths (especially if integrating custom Fontra paths), pristine typography rendering, and zero rasterization of vector elements.
  • Proficient (7–8 points): The export is usable and mostly editable in Adobe software. Some minor cleanup may be required (e.g., clipping masks behaving strangely, or text broken into individual lines rather than paragraphs), but the vector integrity is generally maintained.
  • Developing (5–6 points): The export has significant structural issues. Text may be outlined unnecessarily, CSS styling from the web app fails to translate to the vector export, or bounding boxes are misaligned.
  • Insufficient (0–4 points): The tool fails to export a valid SVG/PDF, or the output is completely rasterized/uneditable in vector software.

05AI Orchestration & Repository Logic

20 points

Core Question: Do the orchestration files (skills.md, handoff.md) within the GitHub repo demonstrate a clear, rigorous command of AI prompting to achieve these specific visual results?

  • Exceptional (18–20 points): The repository documentation reveals a deep understanding of typographic pedagogy used to govern the LLM. The explicit constraints in skills.md strictly map to the visual successes of the tool. The context handoffs are clean, showing targeted iterative debugging of the CSS/SVG math.
  • Proficient (14–17 points): The markdown framework is complete and generally effective. The prompts guide the AI well, though some visual corrections may have been brute-forced rather than solved systematically via rules in the skills.md.
  • Developing (10–13 points): The documentation is sparse or disorganized. The prompts rely on vague aesthetic requests (e.g., “make it look Swiss”) rather than absolute grid coordinates and typographic math.
  • Insufficient (0–9 points): Missing markdown orchestration files, or the prompts show no attempt to systematically constrain the AI’s output.
